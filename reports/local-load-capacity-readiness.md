# Remaining capacity-qualification gaps

Static review on 2026-09-07 (America/Los_Angeles), pinned to root source **`5d7ae681cae586233321270d8f3cd18700fbbca1`**. This maps the existing [production-load protocol](../docs/design/phase6-production-load-protocol.md) to current code and retained evidence; it changes no qualification criteria. Fixtures below are proposed acceptance checks, not executed results or authorization to provision. No benchmark, browser session, network workload or resource-policy change accompanied this review.

Real two-through-six-body admission, scene assertions, authenticated SDK sockets, fixed generator-slot denominators, exact offered/server-accepted reconciliation and owned cleanup already have [functional coverage](local-load-verification.md). Preserve those checks. The protocol's former two-seat-only description was stale; six-body support is not an outstanding implementation gap.

1. **P1 — Full-slot deadline evidence.** [BelayRoom.schedule](../server/BelayRoom.ts) preserves the planned due grid and counts skipped slots, but [local-load-run](../scripts/local-load-run.ts) exposes overlapping completed-callback rings, not the sustained interval's raw slots. **Acceptance:** inject a known bounded scheduler stall; reconcile each active planned slot exactly once, pair due/start/send-enqueue-end, count skips as deadline misses with absent completion, and prove excluded inactive intervals. Recompute full-window, per-room and per-worker nearest-rank tails without averaging percentiles. **Ownership:** server emits bounded timing/lifecycle records; evidence/load validates and aggregates. No solver or catch-up change to improve the score.

2. **P1 — Candidate topology and sustained evidence format.** [LoadAuthority](../scripts/local-load-authority.ts) uses one loopback authority and `getLocalRoomById()` inspection; [server/main](../server/main.ts) creates one persistent test room. Neither exercises a future distributed routing/worker/shared-service arrangement. The [300-room diagnostic](../scripts/local-load-model.ts) lasts 30 seconds; current limits are 120 seconds of input, 180 seconds overall and 64 MiB of reports. At 1,800 clients × 60 inputs/s × 3,600 seconds, its existing ten-byte input planes alone expand to **5,184,000,000 base64 bytes**, before other evidence. **Acceptance:** freeze the exact candidate build/runtime/placement and a separately reviewed production profile with bounded streamed evidence. For a multi-authority candidate, first use a small two-authority ownership/routing fixture through the intended real ingress, with independently placed generators, to enumerate every room once. A one-authority candidate must be labeled and tested as that exact placement. Then apply the approved sustained qualification. **Ownership:** root/platform defines placement and the resource envelope; harness implements observation/adapters. This audit selects no provider and implements no matchmaking or hosting.

3. **P1 — Reserved-body reconnect and its denominator.** `BelayRoom.onLeave()` immediately removes the seat mapping, while the physical body remains; empty nonpersistent rooms can dispose. [LoadGenerator.watch/churn](../scripts/local-load-generator.ts) disables SDK reconnect and deliberately performs fresh joins. **Acceptance:** single-seat and all-seat involuntary outages must preserve room/epoch/body/rope order, advance the reserved world, expire stale controls, prevent seat theft/duplicate owners, and enforce reservation/token boundaries. Measure readiness from independently observed path restoration through fresh same-body state and a new input ACK. Include eligible failures and inside/outside-60-second controls; apply the existing 99.5%-within-five-seconds criterion. A replacement world after worker death is not success. **Ownership:** Phase 4 server/client owns behavior; harness injects faults and reconciles trials.

4. **P1 — Sustained population and active-scene coverage.** Current `completePopulation` uses only the pre-window snapshot; every diagnostic injects churn. The generic square-direction [action script](../scripts/local-load-model.ts) does not prove that expensive gameplay states occurred. **Acceptance:** separate connected endurance from declared fault cohorts; use lifecycle records to catch losses between samples and reconcile physical worlds, logical seats and live transports throughout. Unexpected dips invalidate the connected interval. A frozen mixed-phase and synchronized-burst schedule must observe travel, loaded ropes, bridge collapse/catch/rescue and normal terminal replacement. **Ownership:** load owns population/coverage evidence; game owners supply valid scene and transition contracts. Existing two-through-six-body fixtures are retained, not repeated as a missing feature.

5. **P2 — Actual backpressure coverage.** Existing real read pauses show healthy-partner progress, but [verification](local-load-verification.md) records zero snapshot skips: the server queue-threshold branch was **NOT EXERCISED**. **Acceptance:** a bounded real-socket pause must demonstrably cross `maximumSnapshotBufferedBytes`, observe client-specific skips and bounded queue growth, preserve healthy-client progress, then verify current state and retained-event cursor behavior after resume. If the 256-event history is exceeded, require explicit gap handling. **Ownership:** server owns queue/event policy and observability; harness owns bounded faults and coverage assertions. Do not change thresholds or substitute mocked queue sizes for transport coverage.

6. **P2 — Room memory attribution.** Existing initialized/empty disposal samples and the historical +83,394,560-byte process RSS delta do not separate allocator retention, reachable objects or native/WASM cost. [Wire sizes](local-load-wire-findings.md) are not RAM attribution. **Acceptance:** separately budget fresh-process occupancy rise/fall and connection-only controls; produce exact owned-buffer/capacity counts, exclusive/shared retained-JS paths, native/WASM marginal estimates with uncertainty, unexplained residual and process/container peaks. Keep heap captures outside scored deadline windows. **Ownership:** server/physics identifies ownership and disposal; evidence measures attribution; root/platform sets enforceable headroom. Do not divide process RSS by room count or add `arrayBuffers` to `external`.

These are qualification blockers or coverage gaps, not a capacity verdict. The retained short fixtures, profiles and raw observations remain scoped as documented. The existing guards stay intact; any production profile and evidence budget require their own review before execution.

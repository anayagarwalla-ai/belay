# Rapier contact observation contract

Static source review, 2026-09-08 UTC, BELAY tree `4efb008425ca0ca98958c1a0f2a6574df85523da`. A future adapter can copy Rapier's reported normal contact impulses immediately after its solve. **The installed default solver does not expose usable current tangential impulse components through the JavaScript getters. Neither observation establishes BELAY's current coupled wall-traction budget.** No runtime patch, engine initialization, simulation, measurement, or benchmark was performed.

Installed `@dimforge/rapier3d-compat` is **0.20.0**. Its [published metadata](https://registry.npmjs.org/@dimforge/rapier3d-compat/0.20.0) identifies upstream commit `3e12c2679cb1940a876bde93af9cec0cf2f57944`; its [build manifest](https://github.com/dimforge/rapier/blob/3e12c2679cb1940a876bde93af9cec0cf2f57944/typescript/Cargo.toml#L11) selects the repository's engine crates. Local types and bundled source-map implementations were inspected; upstream implementation conclusions below are pinned to that published revision, not verified by running the binary.

**Observation boundary.** In `shared/expedition-simulation.ts:189`, `world.step()` follows the motor velocity setters. Copy contacts immediately after that call, alongside the predicted poses/velocities at line 190, before any custom correction. Record simulation incarnation, authority tick, internal substep number, a count of completed native steps, phase `post-rapier`, and actual `world.timestep` seconds. The nominal internal rate is 60 Hz under both 30 and 60 Hz authority ticks. An early return at line 153, or terminal-state skip at line 127, produces **no new native observation**, even though the outer substep counter advances.

| Contract item | Exact mapping and interpretation |
| --- | --- |
| Collider/body identity | Enumerate `world.contactPairsWith(bodyCollider, ...)`, then `world.contactPair(bodyCollider, otherCollider, callback)`. Resolve physical player ID through `bodies[id]` and `body.collider(i)`/`collider.parent()`. Resolve terrain through the inverse of `solidColliders` (`solid.id → collider`). Terrain colliders are standalone: `parent() === null` is expected. Rope nodes are not Rapier colliders. Preserve opaque handles with the simulation incarnation; do not truncate or perform integer arithmetic on them. |
| Pair order and normal | Let input A be the climber collider and `n = manifold.normal()`. If `flipped` is false, native side 1 is A; if true, native side 2 is A. The normal impulse on A is **`(flipped ? +1 : -1) * n * Jn`**. Map all side-specific points, feature IDs, subshape IDs, and local normals using the same swap. Keep `n` and the swap in the receipt so orientation is auditable. |
| Geometric contact values | Iterate only `0 ≤ i < numContacts()`. Copy local points, `contactDist(i)`, feature IDs, and `contactImpulse(i)`. The last is `ContactData.impulse`: for contacts written by the solver, the normal impulse accumulated across its internal solver substeps, distinct from the next-step warm-start value. Use N·s with BELAY's kg/m/s convention; dividing by the recorded native duration gives an interval-average force in N, not an instantaneous force. |
| Solver contact values | Separately iterate `0 ≤ j < numSolverContacts()`. Copy solver points/distances, tangent surface velocity, and manifold friction/restitution. Solver index `j` is **not** geometric index `i`: native selection can reorder/reduce contacts, and the internal `contact_id` mapping is not exposed. Solver world points resolve body-local anchors using current body poses, so reading them after BELAY moves bodies changes their meaning. |
| Freshness and absence | Start a new observation each completed native step. No callback means no reported manifold; zero contacts or zero solver contacts are explicit empty/unsolved states. Do not infer touching from pair enumeration, or current impulse from an arbitrary retained geometric point. The getters provide no per-point solve timestamp/membership. Contact recycling can retain geometry. Preserve reported values and counts as native cache observations; do not certify every cached scalar as freshly solved. |
| Removed/invalid objects | Bridge collapse removes colliders before the solve (`:135`). Validate identity/liveness and invalidate its mapping; never carry a removed pair's reaction forward. Null points, unresolved identities, invalid indices, or a skipped native solve mean unavailable data, not a zero reaction. Numeric getters can return zero for an invalid index, which is why bounds checks are required. Sensors belong to the intersection API and supply no contact-impulse observation. |
| Lifetime | Copy plain scalar/vector values synchronously inside the callback. The installed wrapper reuses one `TempContactManifold` and frees its raw wrapper after each callback; raw pointers become invalid on engine mutation/stepping. Do not retain the wrapper, mutate/step the world, await, or recursively query manifolds inside that callback. The adapter does not own/free borrowed wrappers. |

Identity encoding is defined in [handle conversion](https://github.com/dimforge/rapier/blob/3e12c2679cb1940a876bde93af9cec0cf2f57944/typescript/src/utils.rs#L6). The [installed API's upstream binding](https://github.com/dimforge/rapier/blob/3e12c2679cb1940a876bde93af9cec0cf2f57944/typescript/src/geometry/narrow_phase.rs#L95) specifies the getters, bounds behavior, and point conversion; the [TypeScript wrapper](https://github.com/dimforge/rapier/blob/3e12c2679cb1940a876bde93af9cec0cf2f57944/typescript/src.ts/geometry/narrow_phase.ts#L70) specifies order and lifetime. Normal sign follows [constraint construction](https://github.com/dimforge/rapier/blob/3e12c2679cb1940a876bde93af9cec0cf2f57944/src/dynamics/solver/contact_constraint/contact_with_twist_friction.rs#L104). Selection and geometry handling follow [pair update](https://github.com/dimforge/rapier/blob/3e12c2679cb1940a876bde93af9cec0cf2f57944/src/geometry/narrow_phase/pair_update.rs#L403) and [contact storage](https://github.com/dimforge/rapier/blob/3e12c2679cb1940a876bde93af9cec0cf2f57944/src/geometry/contact_pair.rs#L400).

**Tangential capability: unknown under the installed default.** The [native constructor](https://github.com/dimforge/rapier/blob/3e12c2679cb1940a876bde93af9cec0cf2f57944/typescript/src/dynamics/integration_parameters.rs#L9) uses engine defaults; [Simplified friction is the default](https://github.com/dimforge/rapier/blob/3e12c2679cb1940a876bde93af9cec0cf2f57944/src/dynamics/integration_parameters.rs#L10). BELAY does not override it. `contactTangentImpulseX/Y(i)` read `ContactData.tangent_impulse`, but the [simplified solver's writeback](https://github.com/dimforge/rapier/blob/3e12c2679cb1940a876bde93af9cec0cf2f57944/src/dynamics/solver/contact_constraint/contact_with_twist_friction.rs#L777) updates normal totals and separate friction/twist warm-start fields, **not that tangential field**. A zero getter result is therefore not evidence of zero solved friction. Return `solvedTangentialImpulseWorldNs: null`, with reason `not-written-by-default-solver`; retain raw getter values only as explicitly unqualified diagnostics. There is no exposed twist impulse or warm-start world vector to fill this gap.

The basis itself is not inherently unknowable: this revision [constructs it deterministically](https://github.com/dimforge/rapier/blob/3e12c2679cb1940a876bde93af9cec0cf2f57944/src/dynamics/solver/contact_constraint/mod.rs#L28) from `d = -n`, using [its specific orthonormal-vector routine](https://github.com/dimforge/rapier/blob/3e12c2679cb1940a876bde93af9cec0cf2f57944/src/utils/orthonormal_basis.rs#L52), then `t2 = d × t1`. Reproducing that algorithm is source-dependent reconstruction, not a public basis getter; choosing an arbitrary tangent basis or using BELAY's motor axes is invalid. The separate [Coulomb solver does write total tangent components](https://github.com/dimforge/rapier/blob/3e12c2679cb1940a876bde93af9cec0cf2f57944/src/dynamics/solver/contact_constraint/contact_with_coulomb_friction.rs#L678), but that does not repair the current default's missing output. `solverContactTangentVelocity()` is a requested surface velocity in m/s, not friction or a basis.

**Force-event alternative.** BELAY currently supplies no `EventQueue` and enables no contact-force events. A future collector would require `CONTACT_FORCE_EVENTS` on at least one collider, a threshold, `world.step(queue)`, and synchronous copying while draining after each native step. The [actual event construction](https://github.com/dimforge/rapier/blob/3e12c2679cb1940a876bde93af9cec0cf2f57944/src/geometry/mod.rs#L223) sums **normal impulses only** and divides by `dt`: `totalForce` points along native `n` (force on native side 2), `totalForceMagnitude` sums normal magnitudes, and maximum fields describe the strongest normal contact. It supplies no tangential force or complete contact wrench. Missing thresholded events do not prove no contact. The [queue wrapper](https://github.com/dimforge/rapier/blob/3e12c2679cb1940a876bde93af9cec0cf2f57944/typescript/src.ts/pipeline/event_queue.ts) frees borrowed event wrappers after callbacks; the collector itself requires explicit disposal.

The scope here is BELAY's convex cuboid pairs. If composite geometry is introduced, re-audit: native clustering can solve `solver_clusters`, while this JS contact-pair binding enumerates ordinary `manifolds`. [Clustering selection](https://github.com/dimforge/rapier/blob/3e12c2679cb1940a876bde93af9cec0cf2f57944/src/geometry/narrow_phase/pair_update.rs#L349) applies when a pair has multiple manifolds.

**Solver ownership remains unresolved.** BELAY subsequently applies custom rope constraints, body separation, terrain projections, rope routing (`:194–228`), position-derived velocity corrections and inward-velocity removal (`:231–244`), and energy scaling (`:269–286`). Rapier's prior contact solve includes none of those later operations. Keep their deltas/work in separate stages; do not rename them passive Rapier reaction. A previous-step normal impulse can describe history or seed a predictor, but rope load, motor action, geometry, and contact state may change before the next solve. It cannot certify a simultaneous current constraint such as `|Jt| ≤ μ Jn`, particularly when the tangential impulse and later corrections are unobserved. The adapter contract therefore retains `coupledContactCertified: false` and `currentCoupledTractionBudget: null`.
